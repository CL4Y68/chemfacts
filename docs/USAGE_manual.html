chemfacts · 溯源优先化学事实查证 · 使用手册

面向使用者的功能说明、操作指引与可复核证据
版本 v0.3.0 · commit 34b4be4 环境 Windows · Python 3.11.15 (venv) 缓存快照 2026-10-21 · TTL 30 天

本手册说明 chemfacts —— 一个"溯源优先"（provenance-first）的化学事实查证工具：命令行 8 个命令 + 内置 MCP 服务 6 个工具。它回答的问题不是"某物质闪点是多少"，而是"这个数值来自哪、谁测的、什么时候查的、实测还是算的"。三层结构：查询层（CLI / MCP）→ 查证核心（resolve / lookup / verify / crosscheck / card / alias）→ 数据层（SQLite 缓存 + 别名注册表 + PubChem REST）。手册按"设计原理 → 各功能 → 数据层与集成 → 工作流 → 边界"组织；每项功能均附一次真实运行的输出，供逐步复现核对。

查证核心 · 六能力

resolve 身份核验 → lookup 数值带溯源 → verify 宣称值对照 → crosscheck 多源交叉 → card 可审计卡片 → alias 缩写钉位。三态判定（verified / conflict / unverified），缺失即报缺失，绝不填补。

数据层与集成

SQLite 缓存（TTL 30 天，数值可复现）· aliases.json 手工策展（缩写→唯一 CAS）· Obsidian 卡片入库 · MCP 服务（Claude Code / Codex / ZCode / DeepSeek 等任意 MCP 客户端）。

图 1 · 三层架构：查询层与数据层之间的"查证核心"是唯一事实来源，六能力共享同一条解析链路
图 1 说明 · 为什么分成这三层
  1. 查询层只负责"进入"：CLI 供人直接用，MCP 供 agent 直接调；同一核心、同一语义，不存在"CLI 一套答案、MCP 另一套答案"。机器消费走 --json，人消费走 rich 表格。
  2. 查证核心是唯一的判定中枢：resolve 完成"标识符 → 唯一 CAS → CID"的钉位解析；lookup/verify/crosscheck 消费同一缓存做数值对照与判定；card 把结果固化成带出处的可审计记录；alias 管理钉位本身。判定逻辑与展示分离，因此三态结果在六个出口（表格/JSON/卡片/MCP 工具）之间严格一致。
  3. 数据层承载复现性：SQLite 缓存带 TTL（30 天），TTL 内任何输出可逐字复现；aliases.json 是纯 JSON、可 diff、可提交版本控制，钉位修改是有记录的编辑行为，而非"模型记得住"；PubChem 是唯一权威数据源，工具从不把二手来源当权威。

1查证核心：三态判定的化学事实工具 核心

chemfacts 解决的核心问题：把"模型背出来的化学数值"替换为可追溯、可交叉、可审计的带来源数值。三条设计原则贯穿全部命令。

设计原则含义与实现
溯源优先每条数值强制携带四要素：来源名（OSHA / HSDB / CAMEO / ILO ICSC / NIOSH / EPA…）+ PubChem 参考编号 + 查证日期 + 实测/计算属性。缺任一要素即不入缓存，从结构上杜绝"无据数值"。
三态判定 (fail-closed)多源数值交叉核对后落到 verified / conflict / unverified 三态之一。没有带来源的数据就报缺失（no sourced value found），来源打架就摊开每个值让人判，绝不用模型填补、绝不下二元结论。
缩写先钉位含糊缩写（DMPA、H12MDI、BA…）可能指向多种物质；注册表把缩写一次性钉到唯一 CAS 并记录排除理由。钉子是 JSON 条目（可 diff、可版本控制），不是"记得住"。

状态三态与冲突阈值

状态含义触发条件
verified已核验单一来源 / 多来源极差在阈值内 / 差异可归因于闭杯 vs 开杯
conflict冲突极差超阈值且不是杯型差异——工具如实列出每个值，必须人工复核
unverified未查证没有带来源的数值可查——报缺失，不编

各属性冲突阈值（floor）避免把正常来源波动误报成冲突：熔点 ±3 °C、沸点 ±2 °C、闪点 ±1.5 °C、自燃 ±20 °C、密度 ±0.01 g/cm³；其余属性用 10% 相对阈值。闭杯（c.c.）与开杯（o.c.）天然不同，工具识别后不算冲突。

物性 slug（CLI 参数，映射到 PubChem PUG View 标题）

slug（含别名）PUG View 标题
flash-point / flashFlash Point
boiling-point / boiling / bpBoiling Point
melting-point / melting / mpMelting Point

功能一 · resolve：身份核验（标识符 → 唯一 CAS → CID）

使用者输入任意标识符（缩写、名称、CAS），resolve 完成三段解析：若命中别名注册表则先钉位（并打印"为什么钉到它"的注释），再经 PubChem 解析到 CID，返回身份九项 + 出处。这是后续所有数值查询的地基——身份错了，数值全错。

图 2 · resolve 的五段解析链路；实线为数据流，② 为别名注册表拦截点
图 2 说明 · 五段链路各自的职责
  1. ① 用户查询：接受自由文本（缩写 / 名称 / CAS）。"NMP" 本身不含结构信息，不能直接查 PubChem——它需要先被钉位。
  2. ② 别名钉位：注册表命中即输出 pinned via alias 行，且把"为什么"（排除理由）一并打印。这一步把"实验室黑话"转成唯一 CAS，是整条链可审计性的起点。
  3. ③ CAS 解析：CAS → PubChem CID。CAS 是全球唯一的结构标识，从此歧义清零。
  4. ④ 缓存命中：身份九项（名称/IUPAC/CAS/分子式/MW/SMILES/InChI/InChIKey + 出处）落 SQLite；TTL 内复用，保证同快照复现。
  5. ⑤ 溯源结果：最后两行 Accessed / source 给出拉取时间与权威源标记——使用者凭 CID 即可独立回 PubChem 页面核对。

真实输出（NMP，本手册证据快照）

$ chemfacts resolve NMP
pinned via alias: NMP -> 872-50-4  # N-methyl-2-pyrrolidone (solvent)
# ↑ 第②段命中：13 条注册表里 NMP 钉到 872-50-4，注释即"排除理由"（NMP 不作他解）
identity  : N-methyl-2-pyrrolidone
CID       : 13387
CAS       : 872-50-4
IUPAC     : 1-methylpyrrolidin-2-one
Formula   : C5H9NO
MW        : 99.13 g/mol
SMILES    : CN1CCCC1=O
InChIKey  : SECXISVLQFMRJM-UHFFFAOYSA-N
Accessed  : 2026-10-20 13:30:02Z  source: pubchem
# 复核：打开 PubChem CID 13387 页，九项身份与上表逐行一致；
#       MW 99.13 可另按 C5H9NO 手算：5×12.011+9×1.008+14.007+15.999 ≈ 99.13（computed 口径）

功能二 · lookup：带溯源的数值检索

给定标识符与物性 slug，lookup 返回该物性的全部带来源数值（不按状态过滤），每行四要素齐全：数值 | 来源名（参考编号，实测/计算）| 查证日期。使用者自己挑值，工具不替使用者下"哪个对"的结论——判定交给 verify / crosscheck。

真实输出（NMP 闪点，5 个来源摊开）

$ chemfacts lookup NMP flash-point
204 °F                                                       | OSHA (ref #84, experimental) | 2026-10-20
204 °F (96 °C) (OPEN CUP)                                    | HSDB (ref #46, experimental) | 2026-10-20
204 °F (NTP, 1992)                                           | CAMEO (ref #9, experimental) | 2026-10-20
86 °C c.c.                                                   | ILO ICSC (ref #47, experimental) | 2026-10-20
96 °C                                                        | N-Methyl-2-pyrrolidone (ref #44, experimental) | 2026-10-20
# 204 °F ≈ 95.6 °C，与 96 °C 同源同值；86 °C c.c.（闭杯）与 96 °C（开杯口径）差异
# 属杯型差异——crosscheck 会识别 c.c./OPEN CUP 标记，不计入冲突（见 §1 阈值段）
# 复核：ref #47 = ILO ICSC 卡片（按 CAS 872-50-4 公开可查）；ref #44 即 PubChem
#       该化合物参考列表第 44 条——CID 13387 页 → References 可逐条对上
lookup ≠ verify：lookup 只摊开数值与出处，不做判定；"我记的 96 °C 对不对"用 verify，"这个物性可信吗"用 crosscheck。三者消费同一缓存、同一解析链路，答案不会互相矛盾。

功能三 · verify：把宣称值对照全部来源数值

使用者带一个"宣称值"（文献里的、笔记里的、模型记忆里的）来对照：工具归一化单位后，与缓存中该物性全部带来源数值比对，判定逻辑与容差都在输出里写明（within 2%）。三种判定：

判定退出码含义
CONFIRMEDrc 0至少 1 个来源数值与宣称值在容差内一致；输出同时给出 match 行
MISMATCHrc 1全部来源数值都与宣称值超出容差；输出给出最接近的来源值供对照
NOT_FOUNDrc 1该物性没有带来源的数值——宣称值保持未核实，工具拒绝填补

三种判定的真实输出（同一快照）

# ① CONFIRMED：宣称 99.13（NMP 的 MW）与来源值 99.13 一致（容差 2% 内）
$ chemfacts verify NMP mw --claim 99.13
verdict: CONFIRMED
detail : 1 sourced value(s) agree within 2%
closest: 99.13 g/mol (PubChem PUG REST (computed from formula))
match  : 99.13 g/mol (PubChem PUG REST (computed from formula))
# 注意 kind=computed：MW 是 PubChem 由分子式推的，不是实测；复核方式=按 C5H9NO 手算

# ② MISMATCH：宣称 100 °C（TDI_24 闪点）与全部来源值打架，最接近的是 127 °C
$ chemfacts verify TDI_24 flash-point --claim "100 C"
verdict: MISMATCH
detail : claim 100 C not confirmed; closest sourced value: 127 °C (Toluene-2,4-diisocyanate)
closest: 127 °C (Toluene-2,4-diisocyanate)

# ③ NOT_FOUND：NMP 的 explosive-limits 无带来源数值——宣称值原样保持未核实
$ chemfacts verify NMP explosive-limits --claim "0.6-9.0"
verdict: NOT_FOUND
detail : no sourced value found for this property - claim stays unverified
# 设计声明：工具不会把"模型记得的 0.6–9.0%"回填成答案；要核实只能走一手数据库（§4 路径 2）

功能四 · crosscheck：多源交叉核对（该物性的三态判定）

crosscheck 不接收宣称值，直接回答"这个物性的来源数值之间是否一致"，按 §1 的阈值表判三态。CONFLICT 不是错误，是"来源之间真打架"——工具摊开每个值与出处，由使用者判。

状态退出码含义
VERIFIEDrc 0来源一致（或差异仅杯型口径）
UNVERIFIEDrc 0无带来源数值——报缺失，不编
CONFLICTrc 2超阈值且非杯型差异——如实列值，人工复核

三态各一（真实输出）

# VERIFIED：NMP 闪点 5 源一致（杯型差异被识别，不算冲突）
$ chemfacts crosscheck NMP
status: VERIFIED
204 °F                                                       | OSHA (ref #84)
204 °F (96 °C) (OPEN CUP)                                    | HSDB (ref #46)
204 °F (NTP, 1992)                                           | CAMEO (ref #9)
86 °C c.c.                                                   | ILO ICSC (ref #47)
96 °C                                                        | N-Methyl-2-pyrrolidone (ref #44)

# CONFLICT：TDI_24 闪点 6 源，纯品 127 °C vs 80/20 混合品 270 °F，超阈值且非杯型
$ chemfacts crosscheck TDI_24
status: CONFLICT
127 °C                                                       | Toluene-2,4-diisocyanate (ref #36)
127 °C c.c.                                                  | ILO ICSC (ref #43)
260 °F                                                       | NIOSH (ref #73)
260 °F (127 °C)                                              | HSDB (ref #39)
270 °F (EPA, 1998)                                           | CAMEO (ref #6)
270 °F for an 80/20% 2,4/ 2,6 TDI mixture                   | OSHA (ref #59)
# 判读：#36/#39/#43 指纯 2,4-TDI（127 °C）；#59 明写 80/20 混合品 270 °F——
# 冲突根源是物质口径（纯品 vs 商品混合），不是数据错误。使用者按自己用的物质选值并记录。

# UNVERIFIED：IBOA 闪点无带来源数值
$ chemfacts crosscheck IBOA
status: UNVERIFIED
# 不输出任何数值、不用模型记忆填；要数值只能走一手数据库（§4 路径 2）

功能五 · alias：缩写 → 唯一 CAS 钉位注册表

注册表是纯 JSON（默认 ~/.cache/chemfacts/aliases.json，可用 CHEMFACTS_ALIASES 覆盖），每条 = 缩写 + CAS + 排除理由注释（"NOT …"），可 diff、可提交版本控制。示例：H12MDI 钉到氢化 MDI（5124-30-1），明确排除同名的 1,12-二异氰酸酯十二烷（13879-35-1）；IBOA 钉到 C13H20O2（MW 208.30），标注排除了误记的 C13H22O2（210.32）。

钉位是编辑行为，不是模型行为：注册表只接受人工写入（alias add），工具不自动生成缩写映射。每条的 "NOT …" 注释就是可复核的排除证据——把两个 CAS 丢进 PubChem，分子式/MW 不同，即可看到钉位为什么必要。

2数据层与集成：缓存、卡片、MCP 数据侧

数据层承载"复现性"：SQLite 缓存让 TTL 内输出逐字稳定；aliases.json 让钉位可 diff；卡片与 MCP 把带出处的结果送到使用者的知识库与 agent 里。

功能六 · cache：本地检索库管理

$ chemfacts cache show
identity   14
value      224
ref        1227
# 三张表：identity（化合物身份 14 条）/ value（物性值 224 条，每条挂来源）/ ref（参考条目 1227 条）
# 复核基准：TTL 内重跑 §1 各命令 → 数值与参考编号逐字不变，仅 accessed 日期可能刷新；
# cache clear 后重拉 PubChem → 数值/来源应一致（权威源不随快照变），日期更新

缓存目录默认 ~/.cache/chemfacts/（CHEMFACTS_CACHE_DIR 可覆盖）。Docker 部署时以 /data 卷挂载，即多客户端共享的同一份检索库。

功能七 · card：可审计卡片（Obsidian / JSON）

图 3 · 卡片双出口：同一缓存生成两种格式，Obsidian 面向人（wiki 链接、分组），JSON 面向程序（可断言）
图 3 说明 · 卡片为什么必须带 frontmatter 溯源字段
  1. YAML frontmatter：cas / cid / status / accessed / aliases 五项是 Obsidian 侧的"可查询键"——库内 [[]] 双链、Dataview 查询都靠它；其中 status 即三态判定，accessed 即快照日期，缺一个就无法审计。
  2. 属性行格式：数值 — 来源名 (ref #编号, 日期)。ref #编号对应 PubChem 该 CID 的参考列表条目号，凭 CID + 编号即可独立回到一手来源（§4 路径 1）。
  3. 双出口同源：obsidian 与 json 两种格式由同一份缓存生成，字段一一对应；JSON 里的 kind（experimental / computed）让下游程序能写断言（"MW 必为 computed"），而不是人眼判。

功能八 · mcp：让任意支持 MCP 的 agent 按溯源查化学事实

六个能力以 MCP 工具形式暴露（chemfacts-mcp 命令），Claude Code、Codex、ZCode、DeepSeek、Hermes 等任一 MCP 客户端都能调用——agent 拿到的是带溯源的 JSON，而不是模型凭记忆编数。两种传输：stdio（agent 本地拉起）与 streamable-http（Docker，多客户端共享一份检索库）。

MCP 工具参数（对应 CLI）
chemfacts_resolve(identifier) = resolve
chemfacts_lookup(identifier, property) = lookup
chemfacts_verify(identifier, property, claim) = verify --claim
chemfacts_crosscheck(identifier) = crosscheck
chemfacts_card(identifier, format) = card
chemfacts_alias(action, …) = alias（add / show / list / remove）

真实工具调用返回（MCP 客户端拉回的结构化 JSON）

$ chemfacts_verify('NMP', 'flash-point', '96 C')
{
  "ok": true, "property": "Flash Point", "claim": "96 C", "verdict": "confirmed",
  "detail": "1 sourced value(s) agree within 2%",
  "closest": { "value": "96 °C", "source": "N-Methyl-2-pyrrolidone",
               "reference_number": 44, "kind": "experimental",
               "accessed_at": "2026-10-20 13:30:03Z" }
}
# 与 CLI 的 verify 同判同容差（2%）；JSON 版多了 reference_number / kind / accessed_at
# 三字段——agent 生成任何断言时都能把出处一并写进回答

注册方式（各 agent 语法略有差异，命令恒为 chemfacts-mcp，默认 stdio）

# Claude Code
claude mcp add chemfacts -- chemfacts-mcp
# 共享服务（Docker + streamable-HTTP，一个部署给所有 agent）
docker build -t chemfacts-mcp .
docker run -d -p 8000:8000 -v chemfacts-data:/data chemfacts-mcp
# 各 agent 指向 http://<host>:8000/mcp；/data 卷就是共享检索库（facts.db + aliases.json）
已修复（commit 34b4be4）：stdio 模式下启动横幅原先写进 stdout，污染 JSON-RPC 流（客户端日志 "Failed to parse JSONRPC message"）；现仅 http 模式打印横幅，stdio 握手干净。另注：宿机跑全局 HTTP 代理时，访问本地 MCP 服务需设 NO_PROXY=127.0.0.1,localhost。

3常见工作流（照做即可）

五个高频场景，每个给命令序列与复核要点；全部输出基于同一缓存快照。

A · 开反应前查某溶剂的闪点/自燃点（安全）

chemfacts resolve NMP            # 先确认身份（钉位 + CID），避免把 NMP 误解析成他物
chemfacts lookup NMP flash-point # 摊开全部来源闪点（204 °F ≈ 96 °C；86 °C c.c. 为闭杯口径）
chemfacts verify NMP flash-point --claim "96 C"
verdict: CONFIRMED  # 笔记里写的 96 °C 得到来源确认（ref #44），可安全引用

复核要点：CONFIRMED 行带 match 值与来源名；安全操作以最保守口径为准（闭杯 86 °C 低于开杯 96 °C，操作温度控制在 86 °C 以下）。

B · 核实文献/笔记里的一个数值

chemfacts verify NMP mw --claim 99.13
verdict: CONFIRMED  # 99.13 g/mol（kind=computed，按分子式手算可独立复核）
chemfacts verify TDI_24 flash-point --claim "100 C"
verdict: MISMATCH  # 最接近来源值 127 °C（ref #36）——100 °C 查无来源，改引 127 °C 或注明出处

C · 给新缩写钉位（实验黑话进注册表）

chemfacts alias add H12MDI 5124-30-1 --note "hydrogenated MDI (NOT 1,12-diisocyanatododecane)"
pinned H12MDI -> 5124-30-1 (…)
chemfacts resolve H12MDI  # 此后所有查询 H12MDI 走同一 CAS；aliases.json 可 diff / 提交版本控制

D · 批量交叉核对一批物性（脚本可判）

for s in NMP TDI_24 IBOA; do chemfacts crosscheck $s; echo "  rc=$?"; done
# NMP → VERIFIED rc=0；TDI_24 → CONFLICT rc=2（纯品 vs 80/20 混合口径，人工判）；IBOA → UNVERIFIED rc=0（报缺失）
# 注意：参数错误（typer 用法错误）同样 rc=2，脚本里先判 stderr 是否含 "Usage" 再读判定

E · 把查证结果固化进 Obsidian 库 / 交给 agent

chemfacts card NMP --format obsidian --out "F:\Hermes\Obsidian lib\chemical-facts"
# 卡片带 YAML frontmatter（cas/cid/status/accessed/aliases），库内可 [[]] 双链、Dataview 查询
# 或按 §2 功能八注册 MCP 后，agent 直接调 chemfacts_verify 等工具，回答自带溯源 JSON

4边界声明与复现指引

以下边界为系统自身声明，也应在使用者预期中明确；它们不削弱功能，而是界定每个功能能做什么、不能做什么。

边界说明
computed ≠ 实测MW 等 kind: computed 值是 PubChem 由分子式推的，不是实验记录；复核方式 = 按分子式手算（如 C5H9NO ≈ 99.13），而非找实验值。
CONFLICT ≠ 错误是"来源之间真打架"（物质口径 / 测试方法差异，如 TDI_24 纯品 127 °C vs 混合品 270 °F）；工具摊开每个值与 ref #，使用者判，工具不替结论。
UNVERIFIED / NOT_FOUND = 缺失即缺失没有带来源的数据就报缺失，任何宣称值都不因此被视为已核实；要数值只能走一手数据库（ICSC / HSDB / NIOSH 公开页），工具不编。
TTL 30 天的复现窗口TTL 内输出逐字稳定（数值 + 参考编号不变）；cache clear 后重拉，数值/来源应一致、仅日期刷新。跨快照比较数值无意义。
别名注册表 = 人工策展工具不自动生成缩写映射；每条钉位需人工 alias add 并写排除理由。注册表是编辑对象，不是知识源。
退出码 2 的双重含义crosscheck CONFLICT 与 typer 用法错误（缺参数）都返回 rc=2；脚本判定时先检查 stderr 是否含 Usage，再读判定状态。

三条独立复核路径（不依赖本工具）

路径操作
1 · PubChem 参考编号打开 resolve 给出的 CID 页（NMP=13387）→ Experimental Properties → 该物性下列出各来源；ref # 即该页参考列表条目号，来源名（OSHA/HSDB/ICSC…）对得上即通过。卡片 JSON 的 url 字段（PUG View 端点）可直接点开。
2 · 一手数据库ILO ICSC = 国际劳工组织化学品安全卡片（按 CAS 公开可查）；HSDB（NIH 托管）；NIOSH / OSHA / CAMEO 各有公开页。卡片上的数值应能在这些库找到同一条。
3 · 缓存重现cache show 看快照规模（14/224/1227）→ cache clear → 重跑同一命令 → 数值/来源/参考编号应一致，仅 accessed 日期变。一致即"数据可复现"。
